### T001 — Extract shared window-range normalization

> **Historical planning record:** This task preserves the original .NET-only
> rollout scope. Rust Episode support was implemented in later work.

#### Objective

Create one internal source of truth for scope matching and conversion from a
`WindowRecord` to a normalized, bounded `TemporalRange`, then make the existing
comparison preparation path consume it without changing public behavior.

#### Scope

- Create `packages/dotnet/src/Spanfold/Internal/Analysis/WindowScopeMatcher.cs`.
- Create `packages/dotnet/src/Spanfold/Internal/Analysis/WindowRangeNormalizer.cs`.
- Move scope, timestamp, known-at, open-window, horizon, and range construction
  logic out of private methods in `ComparisonPreparer` and into those neutral
  internal helpers.
- Keep selector membership, comparison sides, excluded-record materialization,
  and `ComparisonPlanDiagnostic` construction owned by `ComparisonPreparer`.
- Preserve all existing comparison result, exclusion, diagnostic code,
  severity, message, path, and ordering behavior.

#### Out of Scope

- No public API, namespace, plan-schema, or export-schema changes.
- No episode types or episode runtime.
- No correction of unrelated comparison semantics while moving the code.
- No replacement of `ComparisonSelector`, `ComparisonScope`, or
  `ComparisonNormalizationPolicy`.
- No new diagnostics, validation command, fixture, snapshot, or benchmark.

#### Blocked By

None.

#### Implementation Details

Create the following neutral internal contracts in namespace
`Spanfold.Internal.Analysis`:

```csharp
internal enum WindowRangeNormalizationFailureKind
{
    FutureWindowExcluded = 0,
    MissingEventTime = 1,
    OpenWindowWithoutPolicy = 2,
    MixedTimeAxes = 3,
    InvalidRangeDuration = 4
}

internal sealed record WindowRangeNormalizationFailure(
    WindowRangeNormalizationFailureKind Kind,
    string Reason);

internal readonly record struct NormalizedWindowRange(
    TemporalRange Range,
    ComparisonFinality Finality);

internal static class WindowRangeNormalizer
{
    internal static bool TryNormalize(
        WindowRecord window,
        ComparisonNormalizationPolicy policy,
        TemporalPoint? knownAt,
        out NormalizedWindowRange normalized,
        out WindowRangeNormalizationFailure? failure);
}

internal static class WindowScopeMatcher
{
    internal static bool Matches(WindowRecord window, ComparisonScope scope);
}
```

`WindowScopeMatcher.Matches()` must implement the current `IsInScope()` rules:
optional exact window name, every required segment value, and every required
tag value. Value equality stays `EqualityComparer<object?>.Default` because
that is the current scope-filter contract; this task must not silently change
it.

`WindowRangeNormalizer.TryNormalize()` must preserve these cases:

- processing-position closed range → `TemporalRange.Closed(...)`, `Final`;
- event-time closed range with both timestamps → closed timestamp range,
  `Final`;
- a record starting after a validated processing-position `knownAt` →
  `FutureWindowExcluded` failure;
- a record active at `knownAt` → range clipped to `knownAt` with
  `TemporalRangeEndStatus.OpenAtHorizon`, `Provisional`;
- an open record with an explicit compatible horizon → range clipped to that
  horizon, `Provisional`;
- an open record without a clipping/known-at horizon →
  `OpenWindowWithoutPolicy` failure;
- missing event timestamps → `MissingEventTime` failure;
- incompatible range/horizon axes → `MixedTimeAxes` failure;
- a horizon earlier than the start → `InvalidRangeDuration` failure.

`ComparisonPreparer` must remain responsible for converting failure kinds to
the existing comparison contract:

| Failure kind | Diagnostic code | Severity |
|---|---|---|
| `FutureWindowExcluded` | `FutureWindowExcluded` | Warning |
| `MissingEventTime` | `MissingEventTime` | Error for `Reject`, Warning for `Exclude` |
| `OpenWindowWithoutPolicy` | `OpenWindowsWithoutPolicy` | Error |
| `MixedTimeAxes` | `MixedTimeAxes` | Error |
| `InvalidRangeDuration` | `InvalidRangeDuration` | Error |

Unsupported timestamp known-at remains a plan-level comparison diagnostic. The
caller passes `knownAt: null` to the normalizer when the plan-level check says
known-at cannot be applied. Do not emit one duplicate failure per record.

The helper returns normalized data only. It must not create
`ExcludedWindowRecord`, `ComparisonPlanDiagnostic`, `NormalizedWindowRecord`,
or selector-side membership because those are comparison-specific concerns.

#### Migration Notes

There is no public migration. Existing comparison plans, results, diagnostics,
tests, and exports must remain byte-for-byte or value-for-value equivalent. No
new public namespace is introduced by this task.

#### Misinterpretations To Prevent

- Wrong interpretation: “The neutral normalizer should emit
  `ComparisonPlanDiagnostic` directly.”
  Correct rule: it returns a neutral failure kind and reason;
  `ComparisonPreparer` owns diagnostic code, severity, path, and collection
  ordering.
- Wrong interpretation: “This is an opportunity to fix or simplify known-at
  semantics.”
  Correct rule: preserve current observable behavior; record any discovered
  defect for separate review.
- Wrong interpretation: “Episodes can call the old private methods later, so
  only change their visibility.”
  Correct rule: move the range/scope logic into `Spanfold.Internal.Analysis` so
  neither analytical domain owns the shared rule.
- Wrong interpretation: “A warning failure can be dropped because execution
  continues.”
  Correct rule: preserve excluded-window records and warnings exactly as the
  comparison path does today.

#### Invariants

- Existing comparison normalization behavior and diagnostic output do not
  change.
- A normalized range always has an effective end.
- `Finality` is `Provisional` exactly when the effective range depends on a
  known-at or live horizon.
- Scope matching remains independent from selector matching.
- The helper performs no mutation and no file I/O.
- All failure kinds have an explicit comparison diagnostic mapping.
- No public API or persisted schema changes.
