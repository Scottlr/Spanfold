### T002 — Form deterministic episodes from window history

> **Historical planning record:** This task preserves the original .NET-only
> rollout scope. Rust Episode support was implemented in later work.

#### Objective

Add the first usable `Spanfold.Episodes` vertical slice: select one window
family, normalize its evidence, stitch same-lane fragments into immutable
episodes, and preserve truthful active ranges, lineage, identity, and live
finality.

#### Scope

- Add public episode formation contracts and the `FormEpisodes(...)` fluent
  entry point inside the existing core `Spanfold` project.
- Add internal formation, grouping, union-magnitude, deterministic ordering,
  and identity algorithms.
- Add a small neutral internal temporal-magnitude helper for saturating boundary
  addition/subtraction reused by formation and relationship tasks.
- Support processing-position and event-time histories with axis-specific
  stitch-tolerance overloads.
- Support historical closed evidence, processing-position known-at formation,
  and explicit live horizons.
- Add behavioral tests for formation and finality under
  `packages/dotnet/tests/Spanfold.Tests/Episodes`.
- Add the missing `ComparisonScopeBuilder.Window(string, TemporalAxis)` overload
  so event-time scope can be declared without constructing `ComparisonScope`
  manually; use the same overload from Episodes and Comparison.

#### Out of Scope

- No cross-source episode relationship graph or comparison summary; those are
  T003 and T004.
- No segment/tag-based grouping policy. Segment and tag filters remain scope
  filters, while source fragment metadata is preserved.
- No mutation of source windows and no synthetic window records for gaps.
- No artifact export, CLI command, fixture schema, snapshot format, persistence,
  background execution, or Rust implementation.
- No episode revisions, supersession log, watermark, or late-data completion
  protocol.

#### Blocked By

T001.

#### Why It Is Blocked

Episode formation must consume the same scope and normalized range semantics as
comparison. Starting before T001 would either duplicate private comparison
logic or couple the new namespace to `ComparisonPreparer` internals.

The extension and builder surface must be:

```csharp
public static class WindowHistoryEpisodeExtensions
{
    public static EpisodeFormationBuilder FormEpisodes(
        this WindowHistory history,
        string name);
}

public sealed class EpisodeFormationBuilder
{
    public EpisodeFormationBuilder From(
        Func<ComparisonSelectorBuilder, ComparisonSelector> configure);

    public EpisodeFormationBuilder Within(
        Func<ComparisonScopeBuilder, ComparisonScope> configure);

    public EpisodeFormationBuilder Normalize(
        Func<ComparisonNormalizationBuilder, ComparisonNormalizationBuilder> configure);

    public EpisodeFormationBuilder StitchGapsUpTo(long positionMagnitude);

    public EpisodeFormationBuilder StitchGapsUpTo(TimeSpan duration);

    public EpisodeFormationPlan Build();

    public EpisodeSet Run();

    public EpisodeSet RunLive(TemporalPoint evaluationHorizon);
}
```

`From(...)` and `Within(...)` are required. `Within(...)` must resolve to one
named window family; `ComparisonScope.All()` is rejected in v1 because an
episode definition spanning unrelated window families is ambiguous.
`Normalize(...)` defaults to `ComparisonNormalizationPolicy.Default`.

The tolerance overload establishes its axis:

- `StitchGapsUpTo(long)` means processing-position magnitude;
- `StitchGapsUpTo(TimeSpan)` means timestamp ticks;
- when omitted, the tolerance is zero on the plan's normalized axis;
- negative values and `TimeSpan` values with negative ticks throw
  `ArgumentOutOfRangeException`;
- `Build()` throws `InvalidOperationException` when selector/scope is missing,
  the scope and normalization axes disagree, or the chosen tolerance overload
  disagrees with the normalized axis. It also rejects a normalization containing
  both `KnownAt` and `OpenWindowHorizon`, and rejects any `KnownAt` on an
  event-time plan.

namespace Spanfold.Internal.Analysis;

internal static class TemporalMagnitudeMath
{
    internal static long SaturatingAdd(
        long value,
        long nonNegativeMagnitude);

    internal static long SaturatingSubtract(long left, long right);

```

`SaturatingAdd` rejects a negative magnitude and returns `long.MaxValue` when
the addition would overflow. `SaturatingSubtract` returns `long.MinValue` or
`long.MaxValue` when the mathematical signed difference is outside the `long`
domain. Neither method may wrap.

Formation order is mandatory:

1. enumerate `history.Windows` once;
2. apply `plan.Selector.Matches(window)` and `WindowScopeMatcher`; the public
   selector's `Matches` method is the shared selector authority and must not be
   reimplemented;
3. apply known-at/open-window range normalization through
   `WindowRangeNormalizer`;
4. always omit `FutureWindowExcluded` records from a known-at analysis; omit a
   missing-event-time record only when the configured null timestamp policy is
   `Exclude`; throw `InvalidOperationException` with the source
   `WindowRecordId` and neutral failure reason for every other failure;
5. create `EpisodeFragment` values;
6. group by window name, configured key comparer, source, partition, axis, and
   timestamp clock;
7. deterministically sort groups and fragments by canonical key/source/
   partition values, start, end, and record ID; when custom equality collapses
   differently represented keys, use the first key in this sorted order as the
   episode's exposed representative key;
8. stitch overlapping/touching ranges and positive gaps less than or equal to
   `StitchToleranceMagnitude`;
9. calculate metrics from the union of fragment ranges and materialize the
   result once.

Segments and tags are not part of the formation group. They remain available
through each fragment's `Window`. Distinct timestamp clocks must form distinct
groups even if their timestamp values compare numerically.

Grouping equality is explicit: window name and timestamp clock use
`StringComparer.Ordinal`, key uses the configured comparer for that window
name, source and partition use `EqualityComparer<object?>.Default`, and axis
uses enum equality. Canonical formatting orders groups; it does not replace
these equality rules.

For each episode:

- `Envelope` starts at the earliest fragment start and ends at the latest
  fragment end;
- the envelope end status is effective/provisional only when its terminal
  fragment has an effective end; a closed-but-unsettled episode keeps a closed
  envelope and expresses uncertainty through `Finality`;
- `ActiveMagnitude` is the union length of all fragment ranges;
- `ElapsedMagnitude` is the envelope length;
- `InternalGapMagnitude` is checked `ElapsedMagnitude - ActiveMagnitude` after
  enforcing `ActiveMagnitude <= ElapsedMagnitude`, and cannot be negative;
- zero-length source windows remain zero-length fragments and are not silently
  discarded;
- an ID is derived from structural group values plus ordered record IDs and
  normalized range bounds/status. Do not include the display plan name.

`EpisodeIdentity` must follow the existing `WindowRecordId` convention rather
than process-local hashing: build a length-prefixed invariant-culture UTF-8
payload, hash it with SHA-256, and return lowercase hexadecimal. Prefix the
payload with identity schema `spanfold-episode-v1`, then append window name,
canonical key/source/partition values, temporal axis, timestamp clock,
fragment count, and for each ordered fragment its `WindowRecordId`, start,
effective end, end status, and finality. `EpisodeId.Value` is therefore 64
lowercase hexadecimal characters. This is deterministic .NET identity, not a
Rust-parity or distributed-global promise; a later identity revision requires
an explicit schema change.

`Run()` derives its effective horizon from the built plan. A processing-position
known-at on a processing-position episode plan becomes
`EpisodeSet.EvaluationHorizon`. An explicit
`Normalization.OpenWindowHorizon` also becomes `EvaluationHorizon` and drives
live settling. Reject a policy containing both `KnownAt` and an open-window
horizon. Reject any known-at policy on an event-time episode plan, even when the
known-at point itself is a processing position: Spanfold has no mapping from
that availability position to the timestamp effective end needed to clip an
active fragment safely. Throw before enumeration.

`RunLive(horizon)` clones the execution normalization with
`ComparisonOpenWindowPolicy.ClipToHorizon` and the supplied horizon. Reject an
unknown axis, an axis that disagrees with the plan, or combining `RunLive` with
an independently configured `KnownAt` or `OpenWindowHorizon`; callers must
choose one horizon source. The returned
`EpisodeSet.Plan` must be the effective cloned plan containing that horizon,
not the pre-execution builder plan, so result metadata describes the evidence
that was actually formed.

Finality rules:

- historical closed episodes are `Final`;
- any episode containing a provisional fragment is `Provisional`;
- in a horizon-based run, an otherwise closed episode is `Provisional` while
  `evaluationHorizon <= lastFragmentEnd + stitchTolerance`;
- it becomes `Final` only when the horizon is strictly later than that settling
  boundary;
- calculate the settling boundary with
  `TemporalMagnitudeMath.SaturatingAdd(...)` so a tolerance near
  `long.MaxValue` cannot wrap and mark evidence final early.

var episodes = pipeline.History

    .Normalize(normalization => normalization.OnEventTime())
    .StitchGapsUpTo(TimeSpan.FromMinutes(2))
    .Run();
```

#### Migration Notes

This task is additive. Existing consumers need no changes. The new
`ComparisonScopeBuilder.Window(string, TemporalAxis)` overload does not alter
the existing one-argument overload. Episode IDs are a new .NET-local contract
and are explicitly opaque; no persisted-schema compatibility is introduced.

#### Misinterpretations To Prevent

- Wrong interpretation: “Stitching means replace fragments with the episode
  envelope.”
  Correct rule: preserve every fragment and calculate active magnitude from
  their union; the envelope is elapsed extent only.
- Wrong interpretation: “Two fragments with the same key can stitch even when
  their sources differ.”
  Correct rule: source, partition, axis, and clock are hard formation
  boundaries.
- Wrong interpretation: “Segments must be equal because comparison alignment
  uses segment lanes.”
  Correct rule: segment transitions may be fragments of one episode; retain
  metadata but do not group by it in v1.
- Wrong interpretation: “A closed last fragment makes a live episode final.”
  Correct rule: it remains provisional until the horizon is strictly beyond
  the stitch settling boundary.
- Wrong interpretation: “Sum fragment lengths for active magnitude.”
  Correct rule: union overlapping fragments first, otherwise duplicated source
  evidence inflates activity.
- Wrong interpretation: “Use canonical display strings as key equality.”
  Correct rule: configured key comparers own equality; canonical formatting is
  for deterministic order/identity encoding only.
- Wrong interpretation: “RunLive proves no late event-time record can arrive.”
  Correct rule: finality is relative to the supplied history; no watermark
  claim exists.

#### Invariants

- Formation executes after selection, scope, and normalization.
- Each fragment belongs to exactly one episode.
- Every episode contains at least one fragment.
- Episode fragments remain ordered and read-only.
- Internal gaps remain absent from active coverage.
- `ActiveMagnitude <= ElapsedMagnitude` and `InternalGapMagnitude ==
  ElapsedMagnitude - ActiveMagnitude`.
- Custom key equality is honored in grouping.
- Equivalent custom keys choose the same deterministic representative
  regardless of source-history insertion order.
- Axis and timestamp clock incompatibility never reaches range comparison.
- Results and IDs are deterministic for the same normalized .NET input.
- Historical and live execution perform no writes or background work.
