### T004 — Add analyst summaries and reference scorecards

#### Objective

Turn episode sets and relationship components into compact analyst-facing
answers: occurrence counts, duration distributions, match coverage, count and
magnitude bias, internal fragmentation, split/merge rates, latency
distributions, and an
explicit target-as-reference detection scorecard.

#### Scope

- Add a deterministic magnitude-distribution contract.
- Add a materialized summary to each `EpisodeSet` and
  `EpisodeComparisonResult`.
- Add neutral relationship-query helpers for relation kind and unmatched
  episodes.
- Add an explicit `AsReference()` projection that interprets target episodes as
  authoritative reference occurrences and against episodes as detections.
- Add focused tests for formulas, denominators, graph multiplicity, signed
  distributions, and reference terminology.

#### Out of Scope

- No generic group-by expression tree, cohort DSL, tag/segment grouping, time
  buckets, trend storage, dashboards, or charting.
- No policy pass/fail rules or `Spanfold.Assessment` integration.
- No percentile configuration; v1 has one documented deterministic rule.
- No latency distribution over split, merge, or complex components.
- No automatic declaration that target is ground truth. Neutral summaries are
  always present; reference language requires an explicit method call.
- No artifact/CLI/Rust work.

#### Blocked By

T003.

#### Why It Is Blocked

Correct match counts and magnitudes depend on T003's exhaustive, mutually
exclusive graph components. Computing summaries directly from candidate edges
would double-count episodes in split, merge, and complex relationships.

All helper outputs must be new materialized read-only arrays in the result's
deterministic relation/episode order. `AsReference()` is a pure projection: it
does not mutate the plan/result or change graph classification.

Create the internal calculation seam:

```csharp
internal static class EpisodeSummaryRuntime
{
    internal static EpisodeSetSummary Summarize(
        EpisodeFormationPlan plan,
        IReadOnlyList<Episode> episodes);

    internal static EpisodeComparisonSummary Summarize(
        EpisodeSet target,
        EpisodeSet against,
        IReadOnlyList<EpisodeRelation> relations);

    internal static EpisodeReferenceScorecard AsReference(
        EpisodeComparisonResult result);

    internal static EpisodeDistributionSummary Describe(
        IReadOnlyList<long> values);
}
```

`EpisodeFormationRuntime` owns the construction order: materialize the final
episode array, call `EpisodeSummaryRuntime.Summarize(plan, episodes)`, then pass
both into the internal `EpisodeSet` constructor. `EpisodeRelationRuntime` then
receives two fully constructed sets, materializes relations, calls the
comparison-summary overload, and constructs `EpisodeComparisonResult`. Do not
create a temporary public result with a null summary and do not reconstruct a
set merely to add its summary.

Distribution rules are part of the public analytical contract:

- sort a copied `long[]` ascending;
- `Count` is the number of values;
- `Minimum` and `Maximum` are the endpoints;
- `Mean` uses a deterministic incremental mean over the sorted values rather
  than summing `long` values first, and returns `double`;
- odd median is the central value; even median is calculated as
  `(left / 2d) + (right / 2d)` so adding the two `long` values cannot overflow;
- p95 uses nearest-rank: index `ceil(0.95 * Count) - 1` after sorting;
- an empty distribution has `Count = 0` and every nullable statistic null.

Single-set summary rules:

- all counts derive from the materialized episode/fragment collections;
- totals use `checked` addition and throw `OverflowException` rather than
  wrapping or silently saturating an analytical total;
- mean fragment count is null for an empty set; maximum fragment count is zero;
- multi-fragment count includes episodes with `Fragments.Count > 1`, and its
  rate divides by episode count with null for an empty set;
- magnitude distributions contain one value per episode;
- all episodes in a set must share the plan axis, including an empty set whose
  axis comes from the plan.

Neutral comparison-summary rules:

- matched episode counts include each episode once when its component has both
  sides, regardless of graph degree;
- unmatched counts come only from the matching unmatched relation kind;
- `EpisodeCountBias = AgainstEpisodeCount - TargetEpisodeCount`;
- `ActiveMagnitudeBias = AgainstEpisodes.Summary.TotalActiveMagnitude -
  TargetEpisodes.Summary.TotalActiveMagnitude`, preserving the per-lane episode
  totals users see on the two sets;
- split/merge/complex counts count relation components;
- `SplitTargetEpisodeCount` counts the one target episode in each `Split`
  component; this is relationship splitting, not the same as one episode
  retaining multiple source fragments;
- `MergedAgainstEpisodeCount` counts the one against episode in each `Merge`
  component; complex components are reported separately;
- target/against match rates divide matched side episodes by total side
  episodes;
- split-target rate divides split target episodes by total target episodes;
- merge-against rate divides merged against episodes by total against episodes;
- empty denominators return null, never zero or NaN;
- total coverage and IoU use sums of each component's union magnitudes and
  overlap, so graph edges cannot double-count evidence. These coverage unions
  are deliberately distinct from the per-set totals used by
  `ActiveMagnitudeBias` when a side selector contains overlapping lanes;
- onset, recovery, active-delta, and elapsed-delta distributions include only
  `OneToOne` relations with non-null values.

Reference scorecard rules:

- target episodes become reference episodes only because the caller invoked
  `AsReference()`;
- detected reference episodes are target episodes in any component containing
  an against episode;
- missed reference episodes are unmatched target episodes;
- detection episodes are all against episodes;
- matched detection episodes are against episodes in any component containing
  a target episode;
- unexpected detection episodes are unmatched against episodes;
- `Recall = DetectedReferenceEpisodeCount / ReferenceEpisodeCount`;
- `Precision = MatchedDetectionEpisodeCount / DetectionEpisodeCount`;
- `F1Score = 2 * Precision * Recall / (Precision + Recall)` when both are
  defined; return zero when both are defined and both are zero; return null when
  either denominator was empty.

Do not expose “true positive” counts because split/merge components make a
single scalar TP count ambiguous. The side-specific matched counts above remain
well-defined.

#### Migration Notes

The changes are additive to the T002/T003 types. Their internal constructors
change to require materialized summaries, but no pre-Episodes consumer API is
affected. No serialized contract exists yet, and this task must not create one.

#### Misinterpretations To Prevent

- Wrong interpretation: “Each edge is a successful match.”
  Correct rule: count distinct episodes through exhaustive relation components.
- Wrong interpretation: “Include split and merge onset deltas in percentiles.”
  Correct rule: aggregate latency/duration distributions use one-to-one
  relations only.
- Wrong interpretation: “A complex component is both a split and a merge for
  every member.”
  Correct rule: report complex components separately; do not infer node degree
  from component cardinality.
- Wrong interpretation: “Return zero when a rate has no denominator.”
  Correct rule: return null so absence is distinguishable from measured zero.
- Wrong interpretation: “Target is always ground truth.”
  Correct rule: neutral summary names remain target/against; reference terms
  appear only in the `AsReference()` projection.
- Wrong interpretation: “Use envelope magnitude for active coverage.”
  Correct rule: consume relation component union metrics built from fragments.

#### Invariants

- Summaries are materialized once and remain immutable.
- Match counts never exceed their corresponding side episode counts.
- Relation-component counts sum to `Relations.Count`.
- One episode never contributes twice to a side match count.
- Empty rates are null and no output is NaN or infinity.
- Count and magnitude biases are against minus target.
- Multi-fragment episode rate and cross-side split-target rate remain distinct
  measures.
- Aggregate latency distributions contain only one-to-one relations.
- Reference scoring is explicit, directional, and side-count based.
- Summary calculation performs no I/O and no mutation.
- Summary totals and distribution calculations cannot wrap signed integer
  arithmetic.

#### Acceptance Criteria

- [ ] Single-set summaries report correct counts, totals, fragment measures,
  multi-fragment rates, and deterministic distributions for empty and
  non-empty sets.
- [ ] Comparison summaries report correct match/unmatched/component counts,
  biases, ratios, split/merge rates, coverage, IoU, and one-to-one
  distributions.
- [ ] Split, merge, and complex examples do not double-count episodes or leak
  into one-to-one distributions.
- [ ] Empty denominators yield null; defined zero rates remain zero.
- [ ] `AsReference()` returns the specified recall, precision, F1, missed, and
  unexpected values without modifying the underlying result.
- [ ] Neutral query helpers preserve deterministic result order.
- [ ] The three focused test commands in Implementation Touchpoints pass.
- [ ] No grouping DSL, assessment, artifact, CLI, Rust, fixture, snapshot,
  package-version, or documentation change is included.

snapshots, JSON fixtures, random/property-test infrastructure, or diagnostic
output.

#### Agent Handoff Context

Analysts need compact answers, but the graph remains the evidence authority.
This task is a projection layer over immutable episode relationships. Every
formula must be explainable by side-specific counts or union magnitudes, and
ambiguous components must stay visible rather than being silently assigned.

## Final Notes

- Recommended implementation order: distribution helper, single-set summary,
  comparison summary, query helpers, reference scorecard, then focused tests.
- Unresolved questions: cohort/time-bucket grouping and configurable quantiles
  are deferred.
- Risks: edge double-counting, complex-component overinterpretation, overflow in
  statistical accumulation, and null-versus-zero mistakes.
- Areas that need human review before implementation: any new domain-specific
  success term or metric whose denominator is not uniquely defined.
